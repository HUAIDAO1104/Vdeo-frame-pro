# 视频选图与数量限制审查

审查日期：2026-09-15。源码提交：`9e98b399f29656e40258a483c964004ef63778c1`，对应 Windows 0.2.0 发布后的下载入口与文档同步。此次为逻辑审查，未修改运行代码、模型、默认参数或发布安装包。

## 核心结论

主流程不是“全部候选帧交给 AI 评分”。它是“本地分析全部已提取帧 → 挑出最多 32 帧交给 AI → 混合 AI 分和本地分 → 从全部候选里再选最多 60 帧 → 固定规则制作封面和详情”。

32 是应用写死的预算，不是由模型返回的图片数量限制，也不由视频长度、抽帧上限或用户的质量档位决定。此前重构为控制串行请求数量采用了这个预算，没有证据证明 32 足以覆盖所有题材。没有可见的评分范围选择和覆盖率说明，不适合继续作为唯一策略。

“全部评分”应明确为全部已提取的候选帧，而非原视频每一帧。例如 10 分钟、30 fps 的视频含约 18,000 个原始帧，当前默认最多只提取 120 个候选帧。完整评分可以分多次请求完成，无需把所有图片放入一次请求。

## 实际调用链

`runPrimarySalesAction` / `runSalesKit` → `startImageTasks` → `taskConfig` → `VideoTaskQueue` → `FrameStudio.generate` → `capture` → `inspect` → `diverse(..., 32)` → `visionScoreBatch` → `diverse(..., 60)` → `makeAssets` → `renderAsset` → 发布单个视频的完整结果。

## 当前数量、尺寸与时间限制

| 环节 | 当前约束 | 实际含义 |
| --- | --- | --- |
| 导入视频数量 | 主导入链未设置固定个数上限；重复文件跳过 | 不等于无限容量，已生成项目仍占用内存和缓存 |
| 视频处理并发 | 1 个视频 | 完成一项后才开始下一项，但可提前查看已完成结果 |
| 抽帧上限 | 新用户系统默认 120，允许 1–600 | HTML 初始值为 300，但初始化默认配置会覆盖为 120；已保存设置会覆盖系统默认 |
| 均匀抽帧间隔 | 默认 1 秒；界面 0.1–60 秒 | 浏览器最低 0.1 秒；Rust 实际夹到 0.2–3600 秒，前后端不完全一致 |
| 抽帧数量 | 受时长、间隔和上限共同限制 | 浏览器数量为 min(上限, ceil(范围时长/间隔))，在全范围内取均匀中点；桌面通过加大 fps 间隔满足上限，输出数量与取样时刻可能不同 |
| 场景最小帧间隔 | 界面默认 0.5 秒，范围 0.1–10 秒 | 当前主配置没有传递它，浏览器和桌面新抽帧流程都不使用它 |
| 场景灵敏度 | 界面 10–60，对应阈值约 0.18–0.03 | Rust 再夹到最低 0.05；浏览器用缩略图像素差，桌面用 FFmpeg scene，含义不完全相同 |
| 原始候选图尺寸 | 浏览器长边最多 1920；桌面宽度最多 1920 | 桌面竖屏图高度可以超过 1920，两端的资源预算不一致 |
| 本地分析图尺寸 | 32×18 灰度图 | 用于粗略边缘、曝光和像素差判断；不是精细清晰度或语义理解 |
| AI 评分数量 | min(实际候选数, 32) | 120 或 600 个候选都只发最多 32 个；候选数不超过 32 时才是全量评分 |
| AI 请求批大小 | 每批最多 8 个候选，顺序请求 | 最多 4 批；没有批次并发 |
| AI 图片尺寸 | 宽 480、保持原比例；JPEG 质量 0.7，detail=low | 16:9 输入约为 480×270，精细纹理、脸部细节和轻微失焦信息有限 |
| AI 输出预算 | 每次 max_tokens=1400 | 扩大单批张数时必须同步考虑 JSON 截断，不能只改数量 |
| AI 超时 | 单次网络 75 秒，整批步骤 90 秒 | 任一批失败会使该视频失败；新流程不会自动用本地分完成这一视频 |
| 桌面抽帧超时 | 外层步骤 360 秒；硬件尝试 75–150 秒，CPU 120–240 秒 | 硬件失败可回退 CPU，但两次尝试还受外层步骤预算约束 |
| 自动排序结果池 | min(实际候选数, 60) | 不等于 AI 已评分数，也不等于自动成图实际用到的帧数 |
| 输出版本数 | 界面提供 1 组或 3 组，默认 3 | 分别输出 2 张或 6 张成图 |
| 单张封面 | 4 格 | 3 版封面按排序池交错分组，每版取前 4 个 |
| 单张详情 | 候选数 1–9：9 格；10–14：10 格；15 及以上：15 格 | 按提取帧数量决定布局，未按有效镜头数量或视频主题决定 |
| 画面不足 | 循环复用候选 | 小于 9 帧会提示；有足够帧索引也不代表画面内容足够不同 |
| 自动合成尺寸 | 详情目标宽 1620；封面初始最长边限制 3840；再限制高 14,000、约 22M 像素 | 这是新引擎首次合成的限制，不等于所有编辑、二倍导出路径都有相同最终尺寸 |
| 额外要求 | 界面最多 60 字符 | 可以影响提示词，但不改变 AI 评分数量 |
| 历史记录 | 自动保留最近 20 批 | 是工作批次条数，不是每批视频数；超过后裁掉旧记录 |

旧页面仍保留 `runVisionPick` 的 40 帧、每批 10 帧、210 秒逻辑，以及隐藏的 `aiN`（默认 30、上限 100）。这些不是当前“开始生成”调用链的评分配置。不能拿旧常量解释当前行为。

## 选图问题与影响

### P1：漏评与未评帧入选同时存在

120 帧时 AI 覆盖率最多约 26.7%；600 帧时约 5.3%。32 帧由粗略本地质量、像素差异和时间间距共同选择，没有语义或用户偏好理解；未进入这 32 帧的好画面不会得到 AI 判断。

AI 已评帧使用 0.8×AI overall + 0.2×本地分，未评帧使用 0.5×本地分，然后所有帧重新参与排序。评分依据不一致，未评帧仍可进入最终作品，也可能超过被 AI 明确低评的帧。

候选充足、默认 3 版时，当前布局会使用 33 个不同帧索引，但 AI 最多评 32 个，因此至少有一个自动使用的帧未经 AI 评分。这里的不同指帧索引，不代表视觉内容不同。

### P1：七维评分没有落实到新流程的分用途选图

接口返回 clarity、composition、appeal、theme、subject、detail、overall。新引擎只合并 overall，没有将其余 AI 维度保存在结果 items 中；其中 clarity 保留的是本地粗略指标。

封面和详情沿用同一排序池，详情主要把封面已用帧后移，并没有真正按“封面侧重吸引力、详情侧重信息覆盖”重新打分。设置页“自动按资产类型分别挑图”的描述超过了当前新流程的实现。

### P1：版本差异不足，去重不是硬约束

3 版详情通过把同一排序列表分别移动 0、3、6 个位置构造。在候选充足且每版 15 格时，A/B 与 B/C 都共享 12 个帧，重合率 80%；不是 3 套独立方案。候选只有 15 帧时，3 版详情使用的是同一整组帧，主要变化为排列。

`diverse` 使用质量 0.5、像素差异 0.35、时间间距 0.15 的软打分，没有重复画面的强制排除阈值。同一镜头重复帧、黑场等都可能留在候选和最终输出中。默认场景模式以外不会自动硬过滤转场或重复内容。

### P1：桌面场景抽帧不能保证全片覆盖

桌面用 `select=gt(scene,threshold)` 加 `-frames:v maxFrames`，达到数量上限就结束。若前半段变化多，可能用完预算而没有后半段候选。增加 AI 评分数无法弥补尚未被提取的镜头。

浏览器是先在全范围采样再比较变化，和桌面扫描解码帧的场景检测不同。桌面场景模式没有兜底首帧，静态视频可能返回零帧失败；浏览器保留首个样本。设置中的“最小帧间隔”还未接入主链路。

### P2：上下文、评分追溯和恢复还不完整

- 每批只看到局部 8 帧、候选编号和用户短要求，没有全片主题概览、镜头分组、时间戳，主题代表性和跨批次可比性有限。
- 当前新引擎调用评分时传入空的好图/坏图参考和空的意图 preset，旧路径中的偏好参考能力没有接入这里。
- `aiScores` 中没有每帧“已评/未评”、原始模型七维分和批次状态，结果难以解释。
- 暂停会中断当前请求，继续重做当前步骤；同次运行中此前成功批次仍在内存。停止、失败后重新开始则没有持久化的逐批 AI 评分缓存，新的任务 cacheId 还会导致重新提取。
- 历史自动裁剪至 20 条，桌面删除历史记录只删除数据库行，缺少对无人引用帧缓存的统一回收策略。

## 建议改造顺序

1. 增加可见的 AI 评分范围：“全部候选（完整）”与“限量候选（快速）”，明确显示已提取、已评分、未评分、失败数量。面向选图完整性可默认全量；快速模式才采用可调整预算。不能暗中删除候选后还称为全部评分。
2. 全量仍按小批请求，先测试 2 批并发；失败只重试该批，保存成功批次的模型、参数、图像指纹及评分，支持停止后恢复。改数量时同时调整进度、超时、输出预算与取消逻辑。
3. 已评分帧优先构成 AI 自动选图池；若存在失败或缺失评分，明确提示并由用户选择重试或本地补齐。保持全部候选可手动替换。
4. 保留并校验七维评分；用封面、详情各自的权重和不同镜头约束选图。增加跨版本重合比例约束，独特画面不足时减少候选版本或解释复用。
5. 修复场景抽帧的全片覆盖、最小间隔和静态视频兜底，再考虑长视频自适应抽帧。统一桌面和浏览器可见参数的语义。
6. 用真实视频验证封面吸引力、详情覆盖、重复比例和整批耗时；通过后再决定模型默认值。

请求量参考：仍按每批 8 帧，32 帧为 4 次请求，120 帧为 15 次，600 帧为 75 次。后两者分别为当前满额请求次数的 3.75 倍和 18.75 倍；不是精确费用或耗时倍数，实际由 token 数、线路、并发和重试决定。
