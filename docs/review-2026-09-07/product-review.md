# 帧选 0.2.0 产品审查与优化记录

日期：2026-09-07。审查范围：视频导入、队列生命周期、选图、图片编辑、导出、历史、桌面取消机制和界面设计。基于仓库原版本 `780b982`，在 `codex/streamlined-video-workspace` 实施；未推送或发布。

## 产品方向

核心任务收敛为：**把视频中的画面整理为可编辑、可导出的封面与详情图**。

原版要求先理解文档匹配、销售策略、文案生成和完整批次状态，用户必须承担与图片产出无关的操作。新版默认本地选图，首页只保留导入、候选数量、选图方式与开始。高级抽帧、模型与导出参数放入设置；结果以画面比较和逐格编辑为中心。

## 审查发现与已实施整改

| 优先级 | 发现 | 已实施 | 用户收益 |
| --- | --- | --- | --- |
| P0 | 生成与当前查看的视频共享全局状态 | 提取独立队列与视频处理模块，每个任务拥有独立解码器和参数快照 | 查看上一项时，下一项继续处理；不串视频、不抢切换 |
| P0 | 队列只在整批结束后开放结果 | 每个项目完整产出后立即发布结果 | 可以提前检查、编辑和导出 |
| P0 | 取消只影响前端等待，FFmpeg 可能仍写文件 | 按请求编号取消；杀死并等待子进程退出，再清理缓存 | 删除和停止能实际终止后台提取，避免写入与删除竞态 |
| P0 | 暂停、停止、失败、删除没有清晰生命周期 | 显式状态与检查点；失败隔离、超时提示、停止后可重启 | 操作可预测，失败不会拖住后续视频 |
| P0 | 失败或迟到的结果可能覆盖已有图片 | 完整结果原子替换；取消后禁止发布；绘图使用版本编号 | 保留上次成果，快速连续编辑也不被旧绘图覆盖 |
| P1 | 文档与文案链路超出当前产品任务 | 删除上传、匹配、生成、导出与本机文档接口，移除 Mammoth 包 | 减少输入、耗时、接口费用和无关错误 |
| P1 | 换图、裁剪和撤销后仍需手动生成 | 编辑自动重绘，重绘期间禁止导出旧版本 | 所见与下载结果一致 |
| P1 | 历史恢复后预览标记丢失、队列入口不同步 | 保留生成标记并重绘，恢复后刷新导航与队列控制 | 已编辑图片和主版本选择可恢复 |
| P1 | 删除最后一个视频后，历史仍保留旧批次 | 同步清除当前批次记录 | 已移除内容不会从该记录再次出现 |
| P1 | API 分数按数组位置映射，零分被替换成默认分 | 使用候选编号，保留零分，拒绝重复或缺失编号 | AI 返回顺序变化不再错误对应画面 |
| P1 | 多个主按钮、红绿主题叠加、强装饰分散注意 | 统一浅中性色与紫色操作色，保留单一主行动，清晰区分状态 | 更易判断下一步与当前进度 |
| P1 | 初始即有 4K 标记，容易形成误导 | 默认不加标记，按源视频分辨率检查 | 普通视频不会默认带 4K 标记 |
| P2 | 详情图高度、采样量与内存缺少约束 | 默认 120 个候选，最多 600；单张合成限 22M 像素和 14,000px 高 | 控制极长图和竖屏视频的合成开销 |
| P2 | 原图标辨识度弱，与用途不一致 | 设计深色圆角底、四个画面块和播放符号，替换 Windows ICO、PNG 与网页 favicon | 小尺寸下仍能识别视频与拼图含义 |

## 流程和交互决策

- 主导航只展示视频、结果、历史与设置。未导入视频时禁用生成；没有结果时说明等待条件。
- 正在运行时显示固定的队列控制，完成后缩为普通状态栏。运行中可以切换查看，也可以继续导入；新导入项目留待下次开始。
- 暂停会中断当前步骤，继续后重试。桌面 FFmpeg 提取会重新执行，不宣称毫秒级无损断点续传。
- 停止保留全部已完成图片；删除仅作用于选中的项目。已有结果的删除提供明确确认，并说明不删除源视频。
- 默认生成三组候选，也可选择一组。默认选中 A 版为主封面与主详情，减少导出前的强制操作。
- 短视频使用紧凑详情布局，画面不足时明确提示复用；长视频增加 1/3/2 格行。所有画面可替换或交换。
- 重新生成同一个视频时，旧结果可导出，暂时停用旧结果编辑，防止新版本完成后覆盖同期修改；其他已完成视频正常编辑。
- 导出包含图片和尺寸、源视频、主版本等元数据；无标题、简介、关键词或上架文案文件。
- 小屏改单列，视频列表可滚动；按钮提供焦点状态，详情格子支持键盘进入，提供点选交换以补充拖拽。尊重减少动态效果的系统设置。

## 验证边界与后续优先级

1. **发行前必做**：在 Windows 真机用长视频和不同显卡检查 WebView2、FFmpeg 硬件回退、暂停/删除时的进程退出以及安装升级。此轮在 macOS 编译并测试，未执行 Windows 安装程序。
2. **AI 实机验收**：使用实际接口与视觉模型验证选图质量、网络失败和费用。当前通过的是模拟协议测试，不代表云服务可用性或美学质量保证。
3. **批量容量**：串行处理、候选数和画布上限降低了峰值，但已完成项目仍保留画面与成图，几十个高分辨率视频的长时间内存与磁盘压力尚未压测。下一步可增加图片按需加载和可见的缓存管理。
4. **进一步简化维护**：主队列和处理器已拆分；旧手工帧墙、偏好学习与编辑器仍在原页面脚本中。后续可独立迁移编辑器和设置，避免再次累积覆盖式样式。
5. **历史视频支持**：浏览器受可用存储容量和编码能力约束；桌面历史继续依赖本机源路径与帧缓存。文件被外部移动后需重新导入。
6. **发布状态**：0.2.0 是本地源码与测试构建，尚未替换 GitHub 的已发布安装包。Mac 构建未签名、公证，使用本机已安装的媒体工具。

以上后续事项不影响本次已完成的交互闭环，也不把未验证能力描述为已经通过。
